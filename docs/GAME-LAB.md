# Rebuilt games and the test lab

Open **http://localhost:7070/game-lab**. The page lists all 40 engines, filters by
name, shows each game's saved question mechanic, and loads one game at a time in
a same-origin iframe. Closing or changing a game unloads its timers. Questions
and result events are visible in the lab; **no learner progress is written**.

Each game enters the ready list only after its gameplay tests pass. The status
file is `public/games/remade-status.json`, generated by:

```
node scripts/remade-games-test.js --certify
```

The lab is available without sign-in in development. Its APIs and play frames
require the existing admin gate in production. The surrounding static list page
contains no account data. Existing account authorization and mastery grading on
real course game levels have not been replaced by preview scoring.

## Content fill: code is never part of a model call

The reusable game entry fragments still expose `GAME_ID`, `GAME_DATA`,
`initGame(payload)` and the single `/* __DATA_INJECTION__ */` marker. The existing
question schema and curriculum prompt remain the ordinary course-level contract.
The model fills question text, choices, answers and explanations, not mechanics.

For the lab, one short topic-only prompt generates **50 ethos/logos/pathos
questions once**, cached in `content/game-lab-questions.json` and reused across
the library. The generated source/provider is stated on the page. Replaying,
switching games and opening the lab make **no AI calls**. Difficulty metadata and
balanced answer positions are assigned in code. Hangman takes only entries whose
choices are single words, because its hidden answer must be one word; this can
make its preview pool shorter than 50. Real course Hangman uses its own schema.

```
npm run games:lab:generate
# Cached by default. --force explicitly regenerates the shared pool.
# LAB_PROVIDER=gemini selects that configured provider for this script only.
```

No API keys appear in public content. No extra model subscription or dependency
was added. The GLM attempt failed; the shipped preview set was generated by the
configured Gemini provider. Existing saved course-level question pools still work.

## Engine organization

- `public/games/remade.js`: validation, one-answer locking, feedback, Continue,
  shared cursor, events, lifecycle cleanup, pause, result dialog and replay.
- `public/games/boards.js`: distinct board/card/turn-based rules: tic-tac-toe,
  connect four, memory match, bingo, mancala, snakes and ladders, stakes games,
  hangman, spot-it, Simon, blackjack, war, trash, uno and yahtzee.
- `public/games/arcade.js`: distinct movement/physics: paddle/puck/ball games,
  runners/flyer/bike, snake, traffic, maze, aiming/shooting, pool, flag race,
  swallowing/growth, tower waves and fishing.
- `public/games/engines/tetris.html`: the separately tested 10×20 Tetris engine.
- Other engine fragments are small entry points loading code-owned shared assets.
  `npm run games:build` reproduces them, without changing Tetris.
- The existing lesson loader permits exactly three shared game script URLs,
  loaded in fragment order. This avoids posting the full engine library through
  the 64KB lesson-script body parser. Arbitrary script URLs are still refused.

Games are stylized educational implementations, not copies of commercial assets
or full professional rulebooks. For example, pool uses collision/pocket physics,
archery uses wind and projectile flight, bowling uses collision-based pin totals
rather than tournament strike/spare bonus scoring, and the bike uses jump/wheelie
obstacles rather than a rigid-body motorcycle simulation. Their code owns rules,
controls, bot actions and win/loss conditions; model-generated content cannot
modify them.

## Validation

```
npm run test:games
node scripts/check-game-engine.js
npm test
```

The gameplay harness checks game-specific states and rules plus question gating,
answer events, feedback locking, pause, reinitialization, replay, finish, timer
cleanup and longer-play simulation. Its canvas stub tests physics/state, not
pixels. Tetris keeps its 24 dedicated checks.

For actual Chromium execution:

```
# Start an isolated headless Chrome with --remote-debugging-port=9227.
npm run test:games:browser
```

That check visits all 40 real play frames, verifies initialization, result and
replay controls, catches console exceptions/CSP failures, checks representative
mobile layouts, and tests the embedded lab frame. This is not a substitute for
human play-testing of every possible move, aiming trajectory or full card game.
